💻 Local Windows PC (On-Premises EMR)

Simulates an enterprise hospital or clinical network behind a corporate firewall.

.\SQLEXPRESS (SQL Server 2022) Local PC • Port 1433
Instance hosting the simulated electronic medical records. Reconfigured to Mixed Mode Authentication and TCP/IP Enabled.
Purpose: Acts as the legacy operational healthcare database that needs migration to the cloud.
healthcare_emr_source Database in SSMS
Contains 5 clinical & billing tables (patients, providers, encounters, diagnoses, claims) with 87 total seeded records.
Purpose: Provides realistic relational data including patient PII to test HIPAA de-identification in the lakehouse.
dbo.etl_watermark_control Control Table
Stores table_name, watermark_column, and last_watermark_value initialized to 1970-01-01.
Purpose: Enables metadata-driven delta loading so pipelines extract only new/updated rows without full table scans.
adf_svc_user SQL Login User
Dedicated service account with db_datareader and db_datawriter permissions.
Purpose: Adheres to Least Privilege (no sysadmin rights; can only read tables and advance the watermark table).
DIAHostService (SHIR Agent) Windows Background Service
Installed via Express Setup. Service is running 24/7 on your PC and registered to ADF with key IR@9043c9cc....
Purpose: Connects OUTBOUND to Azure on port 443. The firewall never opens inbound ports, satisfying strict HIPAA network rules.
Phase 1 Environment
☁️ Microsoft Azure Cloud (Central India)

Target enterprise cloud infrastructure within resource group rg-healthcare-migration-prod.

sthealthcarelake01 ADLS Gen2 Storage
StorageV2 account with Hierarchical Namespace (HNS) ENABLED and containers bronze, silver, gold.
Purpose: Houses the 3-layer Medallion Lakehouse. HNS provides instant O(1) directory moves and POSIX ACL permissions.
kv-healthcare-sec01 Azure Key Vault
Configured with modern Azure RBAC. Contains secret sql-onprem-password (HealthLakehouse2026!Secure).
Purpose: Centralizes password storage so no human or code ever hardcodes credentials in pipeline configurations.
adf-healthcare-punit01 Azure Data Factory v2
Enabled with System-Assigned Managed Identity (SMI) and integrated with GitHub repo Azure-Healthcare-Data-Migration.
Purpose: Orchestrates the data migration pipelines. Managed Identity gives it auto-rotating zero-secret tokens to Key Vault and Storage.
ls_keyvault_healthcare ADF Linked Service
Connection from ADF to kv-healthcare-sec01 authenticated via System-Assigned Managed Identity.
Purpose: Allows ADF activities to fetch the SQL Server password on-the-fly during pipeline runs.
ls_sqlserver_onprem ADF Linked Service
Connects via shir-onprem-gateway-01 to DESKTOP-H5RKB3H\SQLEXPRESS using user adf_svc_user and password from Key Vault.
Purpose: The official pipeline data connector that Phase 3 will use as the Source to copy data into Bronze Parquet!

Phase 1 Azure Portal IAM Key Vault Secrets Officer (You) Azure RBAC separates management plane from data plane. This gave your personal account permission to create secrets.
Phase 1 Azure Portal IAM Storage Blob Data Contributor (ADF) Gives ADF permission to write files to ADLS Gen2 containers via its System-Assigned Managed Identity.
Phase 1 Azure Portal IAM Key Vault Secrets User (ADF) Gives ADF permission to read secret values from Key Vault at runtime without granting permission to delete or alter keys.
Phase 1 ADF Studio GitHub: punitgiri921/Azure-Healthcare-Data-Migration Enables Git CI/CD version control. Live code saves to main branch under /adf; ARM templates publish to adf_publish.
Phase 2 Local SSMS healthcare_emr_source Simulated on-premises relational database hosting Patients, Providers, Encounters, Diagnoses, and Claims.
Phase 2 Local SQL Server etl_watermark_control Tracks incremental high watermarks. Prevents full scans and enables restartability if an ADF run fails midway.
Phase 2 Local SQL Server adf_svc_user (db_datareader, db_datawriter) Principle of Least Privilege. Dedicated service login that can read clinical tables and update watermarks without admin rights.
Phase 2 Windows Registry LoginMode = 2 (Mixed Mode) SQL Server Express starts in Windows-Only mode. Setting this to 2 allowed the adf_svc_user SQL login to authenticate.
Phase 2 Windows Services SQL Server Browser = Automatic Resolves the dynamic TCP port for the named SQL Server instance (\SQLEXPRESS) so external processes can find it.
Phase 2 Local Windows Host DIAHostService (SHIR Agent) Bridges your laptop to Azure Data Factory via outbound port 443 HTTPS. No inbound firewall holes needed.
Phase 2 Azure Key Vault Secret: sql-onprem-password Securely stores the HealthLakehouse2026!Secure password in Azure Key Vault.
Phase 2 ADF Studio ls_keyvault_healthcare Linked Service allowing ADF to authenticate to Key Vault via Managed Identity.
Phase 2 ADF Studio ls_sqlserver_onprem Linked Service connecting to local SQL Server through SHIR gateway with password pulled dynamically from Key Vault.
