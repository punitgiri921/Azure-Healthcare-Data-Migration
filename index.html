🏛️ Project Architecture & Data Flow

This platform implements a production-grade hybrid cloud data migration architecture connecting an on-premises healthcare EMR database to Azure via an outbound-only Self-Hosted Integration Runtime (SHIR), incrementally ingesting and transforming data across Bronze, Silver (PII Masking), and Gold (Star Schema) layers in ADLS Gen2.

[ON-PREM SQL SERVER: healthcare_emr_source] -> (Local Loopback) -> [SHIR Gateway: 443 Outbound] -> [ADF Ingestion Pipeline] │ ▼ [Power BI App] <- [Synapse Serverless SQL] <- [Gold Marts] <- [Silver Clean/Mask] <- [Bronze Raw Parquet]
🔐 Enterprise Security & HIPAA Standards Verified
  • Zero-Secret Identity: ADF accesses Azure Key Vault and ADLS Gen2 strictly via System-Assigned Managed Identity (SMI). Database password retrieved dynamically from Key Vault.
  • Outbound-Only SHIR Connectivity: No incoming firewall ports opened on premise. The gateway polls Azure securely on port 443 over TLS 1.3.
  • High-Watermark Idempotency: Dedicated etl_watermark_control table guarantees failure-safe incremental loads without duplicate records.
  • ADLS Gen2 Hierarchical Namespace (HNS): Atomic $O(1)$ folder renames and POSIX-compliant ACLs across bronze, silver, and gold.

CL-01 • Lakehouse Storage
Hierarchical Namespace (HNS) vs Flat Blob Storage
ADLS Gen2 HNS implements a real POSIX-compliant hierarchy. Directory moves and renames execute as instant metadata updates in $O(1)$ constant time rather than copying every nested blob ($O(N)$), which is essential for Lakehouse partition write performance.
CL-02 • Cloud Security
Zero-Secret Architecture via Managed Identity (SMI)
System-Assigned Managed Identity ties an Azure service's identity directly to Microsoft Entra ID. No credentials, connection strings, or master storage keys exist in code. Entra ID handles token generation and automatic 4-hour key rotation behind the scenes.
CL-03 • RBAC Governance
Least Privilege Data Plane vs Management Plane
Assigning Storage Blob Data Contributor grants ADF read/write data access to lakehouse containers without administrative rights over storage networking or billing. Assigning Key Vault Secrets User grants retrieval access without permissions to modify or purge secrets.
CL-04 • DevOps / CI/CD
ADF Git Integration & Multi-Branch Architecture
Connecting ADF to GitHub enables version control. Developer changes save as raw JSON definitions in the main collaboration branch under /adf. When clicking "Publish", ADF automatically generates and commits verified ARM deployment templates into adf_publish.
CL-05 • Incremental Architecture
High-Watermark Metadata Pattern & Idempotency
Dedicated control table etl_watermark_control tracks the high-watermark timestamp for each source entity. Pipeline extracts WHERE updated_at > LastWatermark AND updated_at <= CurrentMax and updates the watermark only upon successful Copy completion, preventing silent data loss.
CL-06 • Hybrid Connectivity
Outbound-Only Self-Hosted Integration Runtime (SHIR)
The SHIR agent establishes outbound HTTPS connections over port 443 with TLS 1.3 to Azure Data Factory service queues. It pulls execution tasks, queries internal on-prem databases over LAN, compresses data into Parquet, and streams it to ADLS Gen2 with zero inbound firewall holes.
TQ-01 • Security Interview Defense
Why use System-Assigned Managed Identity over Storage Account Access Keys in Healthcare?

Senior Architect Candidate Response:

"In a HIPAA-regulated healthcare environment, utilizing Account Keys is an unacceptable security hazard because they offer unfettered root-level access across the entire storage account with no expiration and no granular identity audit trail. By configuring Azure Data Factory with a System-Assigned Managed Identity (SMI) and assigning the `Storage Blob Data Contributor` RBAC role, we implement a true Zero-Secret architecture. Every single data access request is attributed to the ADF service principal in Azure Monitor and diagnostic audit logs, satisfying HIPAA auditability requirements."
TQ-02 • Storage Architecture Defense
Why is Hierarchical Namespace (HNS) mandatory for ADLS Gen2 in Medallion Lakehouse architectures?

Senior Architect Candidate Response:

"In flat Blob storage, directories do not physically exist; they are simply character prefixes in the object URL. In a Medallion Lakehouse where data flows write atomic partitioned batches, moving or renaming a folder in flat storage forces the engine to issue individual copy-and-delete operations for every single blob (O(N) operations). ADLS Gen2 with Hierarchical Namespace (HNS) provides a true POSIX filesystem where directory renames are atomic metadata updates executed in O(1) constant time, drastically reducing pipeline duration and compute costs."
TQ-03 • Network Security Defense
How does a SHIR bridge on-premise databases without opening inbound firewall ports?

Senior Architect Candidate Response:

"Corporate infosec and HIPAA compliance strictly forbid opening inbound ports through enterprise firewalls into on-premise clinical networks. Microsoft SHIR overcomes this by operating entirely on an outbound-only polling model. The SHIR daemon initiates outbound HTTPS connections on port 443 over TLS 1.3 to Azure Data Factory, pulling copy tasks from private queues, extracting data locally, and streaming it out directly to ADLS Gen2. The on-premise network is never exposed to inbound public internet traffic."
TQ-04 • Pipeline Resilience Defense
How do you prevent data loss or duplicate ingestion if an incremental pipeline fails mid-stream?

Senior Architect Candidate Response:

"We enforce strict pipeline idempotency through a two-phase watermark pattern. In the first phase, we capture the static maximum source timestamp into an ADF pipeline variable before starting the copy. In the second phase, the Copy Activity sinks the data to partitioned Bronze storage. Crucially, the stored procedure that updates etl_watermark_control executes only upon successful completion of the Copy Activity. If the pipeline crashes mid-stream, the watermark remains unchanged and the subsequent run re-evaluates the same delta window, eliminating silent data loss."
